# Contributing

Thank you for helping make Baryon AX useful for private infrastructure.

1. Open an issue describing the problem or proposal before large changes.
2. Keep adapters modular: UI, orchestration, retrieval, model integration, and deployment code should not create hidden vendor lock-in.
3. Include tests for behavior changes and update relevant documentation.
4. Never commit credentials, customer data, model weights, or production traces.
5. Submit small focused pull requests with a clear operational impact statement.

By contributing, you agree that your contributions are licensed under MIT.
