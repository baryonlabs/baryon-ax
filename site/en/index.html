Supported formats

Which files can it read?

The parser is selected by file content (MIME), not by the extension. A file with the wrong extension is still routed to the parser that matches its bytes.

The extension is only a hint.

For example, an HWP file named .pdf is detected by its bytes and sent to kordoc. ZIP-based formats are opened to distinguish DOCX, XLSX, PPTX, and HWPX.

Tacit knowledge loop

Why tacit knowledge capture works.

The AI does not invent the answer. It surfaces the judgment your experts already hold and turns it into a searchable, citable, auditable document. The key is that published tacit knowledge follows the same pipeline as any uploaded document.

  1. 01 · DETECT

    Detect

    Answers that lack grounding or are vague are recorded as knowledge gaps, together with the question, reason, and occurrence count.

    record_knowledge_gap · /v1/admin/gaps
  2. 02 · ASK

    Ask

    Open gaps go to the front of the question queue, backed by templates for judgment criteria, onboarding, permissions/exceptions, terminology, and troubleshooting.

    suggest_questions · /v1/tacit/questions
  3. 03 · ANSWER

    Answer

    An expert writes the conclusion plus the reasoning and exception conditions, and can attach existing documents. Only the author or an administrator can edit the draft.

    TacitStore · POST/PATCH /v1/tacit/entries
  4. 04 · PUBLISH

    Publish

    A Markdown document titled # 암묵지: {question} is created and sent through the same parse, chunk, embed, and Qdrant indexing pipeline as an upload.

    POST /v1/tacit/entries/{id}/publish
  5. 05 · VERIFY

    Verify

    Check whether the published answer resolved the original gap, and re-check ontology-pack coverage against its accepted questions.

    knowledge.gap_resolved · verify_pack
  6. 06 · REUSE

    Reuse

    The published document is cited in later chats. Unresolved gaps return to the question queue and the cycle repeats.

    retrieval · citations · GET /v1/tacit/entries

The key

Published tacit knowledge is not a separate FAQ.

Publishing creates a normal Markdown document and runs the same ingest pipeline. That is why it is retrievable, citable, and covered by the same document ACLs — with no second knowledge base to maintain.

questionanswerMarkdownparsechunkembedQdrantcitation

01 · One ingestion pipeline

There is no separate tacit-knowledge store. A published answer follows the same ingest pipeline as any document, so retrieval, chunking, embeddings, and citations come for free.

02 · Provenance to the source

Gap → question → answer → published document stays linked. The provenance panel shows the generation path, original gap, reason, occurrence count, key terms, and published document.

03 · Permissions and audit

Answers and attachments follow organization and role ACLs; only the author or an administrator can edit a draft. tacit.recorded, tacit.published, and knowledge.gap_resolved are written to the audit log.

04 · A loop you can verify

Check whether the published answer resolved the gap. If an ontology pack exists, re-check coverage against its accepted questions. Unresolved gaps return to the queue.

Help

Start here when you get stuck.

The most common issues around installation, models, parsers, retrieval, and permissions — with fixes.

01 · MODEL

The model is always demo-local

If MODEL_BASE_URL is empty, Baryon AX uses the demo model. Set an OpenAI-compatible endpoint and model name. Ollama binds to 127.0.0.1 by default, so containers need a proxy.

.env
MODEL_BASE_URL=http://host.docker.internal:11435/v1
MODEL_NAME=qwen2.5:7b
02 · PARSER

HWP/HWPX uploads fail

The default Compose profile does not include parser sidecars. Start the parser profile and check KORDOC_URL and DOCLING_URL.

Terminal
docker compose -f docker-compose.yml \
  -f docker-compose.parsers.yml \
  --profile parsers up -d --build
03 · RETRIEVAL

Search returns nothing

Without QDRANT_URL, retrieval falls back to lexical search. Connect Qdrant, reindex as an administrator, and check document ACLs, categories, and tags.

API
curl -X POST http://localhost:8000/v1/admin/reindex \
  -H 'X-User-Id: admin' \
  -H 'X-Organization-Id: demo' \
  -H 'X-Roles: admin'
04 · ACCESS

I cannot see the admin menu

In development, set the role with X-Roles: admin. Replace these development identity headers with OIDC/JWT before production.

Headers
X-User-Id: demo-admin
X-Organization-Id: demo
X-Roles: admin
05 · PORTS

Ports are already in use

The UI uses 3001, API 8000, Langfuse 3000, PostgreSQL 5433, Redis 6379, and Qdrant 6333. Change the Compose ports if another service owns them.

Terminal
lsof -i :3001
lsof -i :8000
docker compose ps
06 · DATA

Reset or back up data

Document, audit, feedback, and tacit stores live in Compose volumes under /data. Back up first; deleting volumes is destructive.

Terminal
docker compose logs -f api web
docker compose down
# Deleting volumes loses data. Back up first.

Frequently asked questions

What is Baryon AX?

Baryon AX is an open-source, on-premises AI agent platform that runs grounded RAG over your own documents, tacit knowledge, and memory, then answers with source citations. It ships with organization and role access control, audit logging, and model-agnostic inference, so enterprise knowledge is retrieved, cited, and audited without leaving your network.

What are the minimum hardware requirements?

The Basic Core runs on 2 vCPU, 4GB RAM, and 10GB disk with the demo model. The full stack (Qdrant, PostgreSQL, Redis, Langfuse, Mem0) recommends 8 vCPU, 16GB RAM (32GB recommended), and 100GB disk. GPU inference starts with an RTX 4090 24GB for a 7B model. See hardware requirements.

Does it work in an air-gapped network?

Yes. Baryon AX runs fully offline with no outbound calls required. Mirror the Docker images, model weights, and packages, then keep the model, vector store, and document stores inside your network. See the open-source component and license inventory for what to mirror.

Which models are supported?

Any model that exposes an OpenAI-compatible API. Ollama qwen2.5:7b and vLLM Qwen3.5-27B on B300 GPU 7 are validated. Without a model, the demo-local fallback still demonstrates the UI and flow.

Which document formats are supported?

HWP and HWPX through the kordoc parser, PDF, Office formats (DOCX, XLSX, PPTX), images, and plain text through docling, and legacy formats through Tika, all selected by MIME type. Parsed text is chunked with structure awareness before indexing in Qdrant, and original files stay in your own document store. See supported formats for the complete list.

How do answers stay grounded, and can I check the citations?

Every answer carries document- and chunk-level citations pointing at the exact passage used, and the pipeline trace shows each retrieval and generation step with its latency. When retrieval finds no usable grounding, Baryon AX says so instead of guessing, and source files open only after the requester passes the organization and role ACL check.

Can it parse HWP/HWPX documents?

Yes. The kordoc sidecar parses HWP/HWPX, docling handles PDF, Office, and images, and Tika covers legacy formats. Start the parser profile; MIME-based routing selects the parser automatically.

Where is data stored?

Original files and parsed text live in DOCUMENT_STORE, vectors in Qdrant, audit events in PostgreSQL plus a JSONL mirror, and memory in Mem0/Qdrant. Feedback, tacit knowledge, and knowledge gaps use their own JSONL stores. All stores remain inside your environment.

How is security handled?

Every pull request runs security-sweep for dependency CVEs, secrets, and configuration errors; P0/P1 findings block the merge. A weekly job scans images, SBOMs, and the full git history. For production, follow the security baseline for OIDC/JWT and secret management.

What license is used?

MIT. Commercial use, modification, and distribution are allowed with attribution. See LICENSE.

How do I contribute or report a bug?

Open a GitHub Issue with reproduction steps and expected behavior. Report security vulnerabilities privately using SECURITY.md. See CONTRIBUTING.md for code contributions.

Security CI

Security is not a quarterly review.
It is proven on every PR.

Known vulnerabilities should not depend on human memory. Every pull request runs deterministic scanners for dependency CVEs, secrets, and configuration errors, verifies advisories against OSV, and blocks the merge on P0/P1.

A weekly job tracks images, SBOMs, and the full git history. Results remain in the Job Summary and artifacts as audit evidence.
