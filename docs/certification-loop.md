# 질문–인증 루프: AI가 먼저 묻고, 사람이 인증한다

논문 「암묵지를 끌어내는 인간-AI 인증 루프 설계」(홍승우, HCI KOREA 2027)를 Baryon AX에 구현한 기능입니다.
화면과 상태 모델의 레퍼런스 구현은 [certify-gate](https://github.com/baryonlabs/certify-gate)(MIT)이고, 이 저장소는
그 바깥의 **루프 전체**(라운드, 지식 플랫폼 동기화, 간극 판정, 먼저 묻기)를 맡습니다.

## 왜

조직의 지식 상당 부분은 문서가 아니라 행동 속에 있습니다. 암묵지를 꺼내는 병목은 사람의 기억이 아니라 **무엇을 물어야
하는가**입니다. 그래서 질문의 출발점을 **행동–지식 간극**에 둡니다. 간극이란 사람이 실제로 한 결정 가운데 기존 지식으로
이유가 설명되지 않는 것입니다. 모든 행동을 묻지 않고 간극만 골라 물으며, 정답 대신 **예상 답 3개**를 발판으로 보여 줍니다.

## 한 라운드

| 단계 | 하는 일 | 어디서 |
| --- | --- | --- |
| ① 온톨로지 | 회사 전체가 볼 수 있는(member) 문서(업로드·웹·슬랙 대화)를 라운드마다 몇 조각씩 이어 읽어 끝까지 읽고, 용어(정의·근거 문장)와 관계를 뽑습니다. 근거 문장이 원문에 글자 그대로 있으면 **확인됨**, 아니면 **초안**. 같은 용어를 문서마다 다르게 정의하면 **[쟁점]**으로 두 해석을 모두 보존 | `POST /v1/loop/rounds` |
| ② 기록 | 동의한 사람이 글을 쓰거나 고치면 스레드 전체를 한 번 읽고(`POST /v1/loop/threads/understand`), 그 글에서 사람이 말로 확정한 결정("운송비는 빼고 견적 내자", "정산 기한은 2주가 맞아")과 "아직 안 정했어"라고 한 것만 직전 대화와 함께 기록. 부탁("정리해 줘"), 다른 봇의 정리, 반응으로만 동의한 제안, 끊긴 글은 기록하지 않음. 스레드에 이유가 적혀 있거나 앞서 나온 값을 확인한 결정은 질문하지 않음 | 슬랙 봇, `POST /v1/loop/actions` |
| ③ 판정 | 행동과 관련된 온톨로지 항목·문서를 찾아, 그 행동의 **이유(기준·조건)를 진술하는지** 판정. 진술하지 않으면 간극 | 라운드 |
| ④ 질문 | 간극마다 질문 1개와 예상 답 3개(원칙·조건·기대 결과, 각 40자 안팎). 화면은 '모두 틀림'과 자유 입력을 함께 보여 줌 | 슬랙 DM |
| ⑤ 답 | 고른 답 + 덧붙인 조건, 또는 직접 쓴 기준이 **기준(criterion) 항목**이 됨. 1차 출처는 기록된 행동과 그 답 | `POST /v1/loop/questions/{id}/answer` |
| ⑥ 인증 | 초안 → 확인됨(에이전트 가능) → **인증됨(사람만)**. 모든 출처를 대조해 체크하고 [쟁점]을 고른 뒤에만 서명. 보류·거부는 사유 필수, 초안으로 돌아감 | 슬랙 인증 카드, `POST /v1/loop/items/{id}/decision` |

인증된 기준은 문서(`certified` 태그)로도 등록되어 채팅 답변의 근거가 되고, 의사결정용 조회(`/v1/loop/decision-kb`)에는
인증된 항목만 나옵니다.

## 서버가 강제하는 것

- 에이전트(역할 `agent`·`service`, `LOOP_AGENT_USERS`의 봇 계정)는 인증·보류·거부를 할 수 없고, 질문에 답할 수 없습니다.
- 서명 요청에 대조한 출처 번호(`checked`)가 하나라도 빠지면 409 `gate_incomplete`. [쟁점]은 해석 선택이나 사유가 있어야 합니다.
- 기준 항목은 답한 사람(또는 관리자)만 인증합니다. 거절·인증 시도는 모두 감사 로그(`loop.decision`, `loop.decision_refused`)에 남습니다.
- 문서에서 뽑은 용어가 '확인됨'이 되려면 근거 문장이 원문에 있어야 합니다(`source_mismatch`).

화면이 보장하는 것은 **대조 절차**이지 판단의 정확성이 아닙니다(논문 5장: 읽지 않고 체크만 하면 오류가 통과할 수 있음).

## 슬랙에서

| 할 일 | 방법 |
| --- | --- |
| 기록에 동의 | 관리자가 `LOOP_SLACK_USERS=U123,U456`에 추가 (모두 기록하려면 `*`, 동의를 받은 경우만) |
| 먼저 묻기 | `LOOP_INTERVAL_MINUTES`(기본 60)마다 라운드를 돌리고, 새 질문을 그 사람에게 DM으로 보냄 (한 라운드에 사람당 `LOOP_MAX_QUESTIONS`개) |
| 지금 묻기 | `@baryon 나한테 질문 있어?`, `@baryon 먼저 물어봐` |
| 답하기 | 예상 답 버튼 → 조건 덧붙이기(선택) / **모두 틀림** → 실제 기준 쓰기 / **직접 쓰기** / **나중에** |
| 인증 | 답하면 인증 카드가 옴: AI 초안과 원문을 나란히, 원문마다 "대조했어요" 체크 → **서명(인증)** / 보류 / 거부(사유) |
| 인증할 것 보기 | `@baryon 인증할 것` |

## 내보내기

- `GET /v1/loop/ontology` — certify-gate와 같은 `ontology.json`(`terms / relations / questions`), 상태·출처·쟁점 포함.
  `?certified_only=true`는 인증된 것만.
- `GET /v1/loop/ossie` — Apache Ossie 의미 모델. 필드 설명이 `[certified]`·`[verified]`·`[draft]`로 시작해 받는 쪽이
  인증된 것만 골라 쓸 수 있습니다.
- `GET /v1/loop/stats` — 상태별 항목 수, 쟁점, 행동·질문 현황, 온톨로지로 읽은 문서·조각 수(`ontology_coverage`), 마지막 라운드.

## 설정

| 변수 | 기본 | |
| --- | --- | --- |
| `LOOP_STORE` | `$ONTOLOGY_STORE/loop` | 조직별 JSON (볼륨에 둠) |
| `LOOP_AGENT_USERS` | `slack-bot,discord-bot,baryon-agent` | 사람이 아닌 계정 |
| `LOOP_ENABLED` (슬랙) | `true` | 끄면 기록·질문·인증 카드 모두 꺼짐 |
| `LOOP_SLACK_USERS` (슬랙) | 비어 있음 | 기록에 동의한 사람. 비어 있으면 기록과 정기 라운드 없음(요청 시 질문·인증은 동작) |
| `LOOP_INTERVAL_MINUTES` (슬랙) | `60` | 0이면 정기 라운드 끔 |
| `LOOP_DOCUMENTS_PER_ROUND` (슬랙) | `5` | 한 라운드에 온톨로지로 읽을 문서 수(문서마다 4조각씩, 다음 라운드에 이어 읽음) |
| `SLACK_ARCHIVE_CHANNELS` (슬랙) | 비어 있음 | 하루 대화를 문서로 남길 채널(`*` = 봇이 들어간 모든 채널) |

## 한계

- 행동 기록은 동의와 열람·삭제 권한이 전제입니다. 기본값은 아무도 기록하지 않습니다.
- 간극 판정은 모델의 판단이고, 논문의 합성 평가(F1 0.95)는 현장 정확도를 뜻하지 않습니다. 예상 답은 정답이 아닙니다.
- 사람 참여자 검증(논문 표 5)은 후속 과제입니다.
