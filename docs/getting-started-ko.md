# Baryon AX 사용 안내: 무엇을 할 수 있나요

전체 기능 요약입니다("기능을 설명해 줘", "뭘 할 수 있어?", "어떻게 써?"에 대한 답). Baryon AX의 기능은 다섯 가지입니다.
1. 근거 있는 답변: 사내 문서로 답하고 출처(문서·청크)를 붙임. 문서에 없으면 지어내지 않음.
2. 먼저 묻기: 답하지 못한 질문을 지식 공백으로 모아 전문가에게 먼저 묻고, 답을 게시하면 지식이 됨. 온톨로지 꾸러미로 정리. 또 사람의 결정 가운데 문서로 설명되지 않는 것만 골라 예상 답 3개와 함께 먼저 묻고, 답을 원문 대조 후 사람이 인증(질문–인증 루프).
3. 문서·코드·웹 올리기: HWP·PDF·Office·이미지 문서, 질문에 넣은 웹 페이지 링크, git 저장소의 문서·코드 지도·변경 이력. 문서별 열람 권한과 감사 로그.
4. 쓰는 곳: 웹 채팅, 슬랙 봇(@멘션·DM·첨부 파일 읽기·문서로 추가·비서에게 일 맡기기), 음성 비서 앱(전화·할 일·알림·사진·녹음·메일 초안), 다른 AI 도구(MCP).
5. MCP: Baryon AX가 MCP 서버로 도구 6개(search_documents, ask, list_knowledge_gaps, suggest_questions, record_answer, publish_answer)를 제공하고, 음성 비서는 MCP로 메일·일정·슬랙·목표 에이전트·알림·DureClaw 플릿에 연결됨.
이 문서는 웹 채팅, 슬랙 봇, 음성 비서가 기능 안내의 근거로 씁니다. 슬랙에서 "설명서 알려줘", "사용법", "도움말"이라고 물으면
봇이 이 문서 전체를 읽고 자세히 설명합니다. 자세한 내용은 아래 각 절에 있습니다.

MCP 연결 요약("MCP는 뭐가 연결돼 있어?"에 대한 답):
- 밖으로 제공: Baryon AX MCP 서버(`POST /mcp`) 도구 search_documents, ask, list_knowledge_gaps, suggest_questions, record_answer, publish_answer, crawl_site(웹사이트 크롤링).
- 음성 비서가 쓰는 MCP 연결: baryon-ax(사내 지식), goals(목표 에이전트), memory(기억), phone(알림·알람), screen(화면 카드), slack(슬랙), DureClaw(다른 머신·카카오톡), 사내 할 일, gog(메일·일정).
- 켜고 끄기: 앱 설정 > 비서에게 알려 주기 > 연결(MCP). 실제 연결 목록은 설치마다 다름.
- 별도로 SaaS 커넥터 레이어(`/v1/connectors`, Slack·SAP 등)는 1단계(목록·도구 검색)만 구현되어 있음.

## 한 줄 소개

Baryon AX는 회사 문서로 근거를 들어 답하는 사내 AI입니다. 답하지 못한 질문은 전문가에게 먼저 물어 회사의 지식으로
쌓습니다. 같은 지식을 웹 채팅, 슬랙, 전화 비서, 그리고 MCP를 지원하는 다른 AI 도구에서 씁니다. 모든 것이 회사 서버
안에서 돌고, 문서와 음성은 밖으로 나가지 않습니다.

비유하면 사내 검색(Glean), 온톨로지(Palantir), 근거 대화(ChatGPT Enterprise), 메신저 에이전트(Slack AI),
상주형 비서(OpenAI dots · Pickle)를 회사 서버 하나에서 쓰는 것과 비슷합니다. 제품명은 이해를 돕기 위한 비유입니다.

## 어디서 쓰나요

| 쓰는 곳 | 하는 일 | 시작하는 법 |
| --- | --- | --- |
| 웹 채팅 | 질문하면 사내 문서로 답하고, 답 아래에 출처(문서·청크)를 붙입니다. 문서 올리기, 지식 공백·암묵지 관리, 감사 로그 | 브라우저에서 Baryon AX 주소로 접속 |
| 슬랙 봇 | 채널에서 봇을 @멘션하면 같은 지식으로 답하고 근거를 붙입니다. 같은 스레드의 다음 질문은 멘션 없이 이어서 답합니다 | 봇을 채널에 초대하고 `@봇이름 질문` |
| 음성 비서 (바리온 비서 앱) | 전화하듯 말로 묻고 맡깁니다. 메일·일정·할 일 요약, 일정 조정, 코딩·조사를 목표 에이전트에 맡기기, 알림·알람 | 안드로이드 앱 '바리온 비서'에서 통화 버튼 |
| MCP 클라이언트 | Claude, Cursor 같은 AI 도구가 Baryon AX 지식을 도구로 씁니다 | MCP 서버 주소 `POST /mcp` 등록 |

## 슬랙 봇 사용법

슬랙 봇(예: `@baryon`)은 웹 채팅과 같은 지식으로 답합니다. 묻는 사람마다 따로 권한·감사 로그가 남습니다.

### 1. 질문하기

1. 봇을 채널에 초대합니다: 채널에서 `/invite @baryon`. 비공개 채널도 같습니다.
2. `@baryon 연차휴가는 며칠이야?`처럼 멘션하고 질문합니다. 처리하는 동안 👀 반응과 "문서를 찾아 답변을 준비하고 있습니다…"가 보입니다.
3. 답 아래에 **근거**(문서 이름·조각 번호·인용)가 붙습니다. 문서에서 답을 찾지 못하면 그렇게 말하고, 그 질문은 지식 공백으로 남아 전문가에게 갑니다.
4. 같은 스레드에서는 멘션 없이 이어서 물어도 됩니다("그럼 해외는?"). 앞선 대화를 함께 읽고 답합니다.
5. 봇과의 1:1 **DM**에서는 멘션 없이 바로 묻습니다.
6. "설명서 알려줘", "사용법 자세히", "도움말", "뭘 할 수 있어?"는 이 사용 안내서 전체를 읽고 답합니다. "슬랙에서 파일은 어떻게 올려?"처럼 기능을 짚으면 그 부분을 단계별로 설명합니다.

### 2. 파일 읽기와 문서로 추가

1. 스레드에 파일을 올립니다(HWP·HWPX·PDF·Word·Excel·PowerPoint·이미지·텍스트·`.zip`).
2. 그 스레드에서 `@baryon 이 파일 읽고 요약해 줘`, `@baryon 엑셀 분석해 줘`라고 하면 파일을 문서로 등록한 뒤 그 내용으로 답합니다.
3. `@baryon 문서로 추가해 줘`는 첨부 파일을 지식으로 등록만 합니다. 첨부가 없으면 스레드의 글을 Markdown 문서 하나로 등록합니다.
   "문서로 추가하고 분석해 줘"는 등록과 분석을 함께 합니다.
4. `.zip`은 풀어서 안의 파일을 하나씩 등록합니다(한국어 파일명, 폴더 구조 유지, `__MACOSX` 같은 군더더기는 건너뜀). 한 번에 30개, 파일당 20MB까지입니다.
5. **사진·스크린샷·스캔 PDF**는 OCR로 글자를 읽습니다(한국어 기본). 영수증·명함·공문 사진을 올리고 "읽어 줘"라고 하면 됩니다.
6. 등록한 문서 목록은 엑셀 파일로 스레드에 붙습니다. 같은 파일을 다시 물으면 다시 올리지 않고 등록된 문서를 씁니다.

### 3. 링크와 웹사이트

- 질문에 웹 주소를 넣으면 그 페이지를 읽고 답합니다: `@baryon https://www.example.com/ 이 회사가 뭘 하는지 정리해 줘`.
- 사이트 전체는 `@baryon https://www.example.com/ 이 사이트 크롤링해 줘`. 백그라운드로 읽어 문서로 저장합니다.
- 슬랙 메시지 링크를 넣으면 그 스레드를 읽고 함께 답합니다(봇이 들어가 있는 채널만).

### 4. 비서에게 일 맡기기 (비서 주인만)

음성 비서가 함께 설치되어 있으면, 비서의 주인(설정 `SECRETARY_SLACK_USERS`)이 슬랙에서 맡긴 **일**은 비서가 처리합니다.

1. 일을 맡기는 말(초안, 메일, 보내, 연락, 일정, 예약, 만들어, 작성, 해 봐, 전략, 시나리오)이나 "비서 …"로 시작하면 비서에게 갑니다.
   예: `@baryon 위의 내용을 구글 메일 초안으로 올려 두고 링크 줘`, `@baryon 비서 오늘 일정 정리해 줘`.
2. 비서는 스레드의 앞선 메시지와 첨부 파일(사진은 이미지로, `.zip`은 풀어서, 글 파일은 내용으로)을 함께 읽습니다.
3. 진행 중에는 "비서가 일하고 있어요…"와 한 일이 보이고, 결과·초안·표는 카드로 붙습니다.
4. 메일 보내기처럼 바뀌는 일은 **진행/취소 버튼**으로 확인합니다. 스레드에 "응", "아니"로 답해도 됩니다. 버튼은 주인만 누를 수 있습니다.
5. 메일 초안은 Gmail 임시보관함에 저장되고 **Gmail에서 열기** 링크가 옵니다. 링크에서 직접 고쳐 보내도 됩니다.

### 5. 먼저 묻기 (전문가 채널)

- 관리자가 '먼저 묻기' 채널을 정하면, 봇이 쌓인 지식 공백을 그 채널에 질문으로 올립니다.
- 전문가가 스레드에 답하면 초안이 되고, **문서로 등록** 버튼을 누르면 다음 질문부터 근거로 쓰입니다. 해당 없으면 **해당 없음**.

### 6. AI가 먼저 묻는 질문 (질문–인증 루프)

- 기록에 동의한 사람(`LOOP_SLACK_USERS`)이 슬랙 스레드에서 말로 확정한 결정 가운데 **스레드와 회사 문서로 이유가 설명되지 않는 것**만 골라,
  봇이 DM으로 먼저 묻습니다: 질문 하나와 예상 답 3개(원칙·조건·기대 결과), '모두 틀림', '직접 쓰기', '나중에'.
- 예상 답을 고르면 조건을 한 줄 덧붙일 수 있고, '모두 틀림'이면 실제 기준을 씁니다. 답은 **기준 초안**이 됩니다.
- 이어서 **인증 카드**가 옵니다. AI 초안과 원문(기록된 행동, 내 답)을 나란히 보고 원문마다 "대조했어요"를 체크한 뒤
  **서명(인증)** 합니다. 체크를 빼먹으면 서버가 거절합니다. 보류·거부는 사유를 적고 초안으로 돌아갑니다.
- 인증된 기준만 답변의 근거와 의사결정에 쓰입니다. 같은 루프가 문서에서 용어와 관계(온톨로지)를 뽑고, 문서마다 정의가
  다르면 [쟁점]으로 두 해석을 모두 보존합니다. Apache Ossie로 내보낼 수 있습니다(`GET /v1/loop/ossie`).
- 관리자가 켜 두면(`SLACK_ARCHIVE_CHANNELS`) **채널의 하루 대화도 문서 한 개**가 되어 검색되고 온톨로지로 읽힙니다. 봇 글과 DM은 빼고, 비공개 채널은 관리자만 봅니다.
- 바로 해 보기: `@baryon 나한테 질문 있어?`, `@baryon 인증할 것`. 자세한 내용은 docs/certification-loop.md.

### 7. 슬랙 봇 권한과 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 파일을 받지 못했다 / files:read 권한이 없다 | 봇 토큰에 `files:read` 범위 없음 | 슬랙 앱 설정 OAuth & Permissions에 `files:read`(목록 엑셀은 `files:write`) 추가 후 **Reinstall to Workspace** |
| DM에 답하지 않음 | `im:history` 범위, `message.im` 이벤트, App Home의 Messages Tab | 범위·이벤트 추가, Messages Tab 켜기, 앱 재설치 |
| 멘션 없는 후속 질문을 못 알아들음 | `channels:history`/`groups:history` 없음 | 범위 추가 후 재설치 (멘션 질문은 그대로 동작) |
| 비공개 채널에서 반응 없음 | 봇이 채널에 없음 | `/invite @baryon` |
| "비서가 응답하지 않아요" | 음성 비서 서버가 꺼짐 | 관리자에게 비서 서버(`SECRETARY_URL`) 확인 요청 |
| 사진의 한국어가 안 읽힘 | 파서(docling)가 없거나 꺼짐 | 관리자가 파서 사이드카(`--profile parsers`)를 켬 |

## 기본 기능

### 1. 근거 있는 답변

- 질문하면 열람 권한이 있는 문서에서 관련 부분을 찾아 답합니다.
- 답 아래에 어느 문서의 몇 번째 조각을 썼는지 출처가 붙습니다.
- 문서에 없는 내용은 지어내지 않고 "문서에서 찾지 못했다"고 말합니다. 그 질문은 지식 공백으로 기록됩니다.

### 2. 모르는 질문은 전문가에게 먼저 묻기

- 답하지 못한 질문은 **지식 공백**으로 모입니다.
- 사용률이 낮은 시간에 공백을 정리해 담당 전문가에게 먼저 질문합니다(웹, 슬랙의 '먼저 묻기').
- 전문가의 답은 초안으로 저장되고, 게시하면 다음 질문부터 근거로 쓰입니다.

### 3. 문서 올리기

- 웹 채팅의 지식 화면에서 파일을 올립니다. 여러 파일을 한 번에 올리고 카테고리·태그를 붙일 수 있습니다.
- 기본 형식은 텍스트·Markdown입니다. 파서를 함께 설치하면 HWP·HWPX, PDF, Word·Excel·PowerPoint, 이미지도 읽습니다.
- 표와 제목 구조를 살려 나누므로, 답의 출처가 "어느 제목 아래 어느 표"로 나옵니다.

### 4. 권한과 감사

- 문서마다 볼 수 있는 역할(예: 멤버, 관리자)을 정합니다. 권한이 없는 문서는 검색에도 나오지 않습니다.
- 질문, 답변, 문서 변경은 모두 감사 로그에 남습니다. 슬랙에서 물은 질문도 사람별로 기록됩니다.

### 5. 온톨로지

- 지식 공백이 쌓이면 사람·업무·용어의 관계를 정리한 **온톨로지 꾸러미**를 만듭니다.
- 꾸러미는 "아직 모르는 값"(예: 법인카드 해외 결제 한도 = ?)을 보여 주어, 전문가가 무엇을 채워야 하는지 알 수 있습니다.

### 6. 웹 페이지 읽기

- 질문에 링크를 넣으면("https://www.example.com/ 이 사이트 이해해 줘") 그 페이지를 읽어 지식으로 저장하고, 그 내용을 근거로 답합니다.
- 같은 주소는 24시간 동안 저장한 것을 다시 쓰고, 그 뒤에 물으면 새로 읽습니다.
- **사이트 전체 크롤링**: 웹 지식 화면의 '웹사이트 크롤링'에 주소를 넣거나, 채팅·슬랙에서 "https://… 이 사이트 크롤링해 줘"라고 말합니다.
  사이트맵과 링크를 따라 같은 사이트의 페이지를 최대 200쪽까지 백그라운드로 읽어 문서로 저장하고, 진행 상황(읽은 쪽 수)이 화면에 보입니다.
  경로 제한(예: `/docs`)으로 일부만 읽을 수 있고, 내용이 같은 페이지(`/`와 `/index.html`)는 한 번만 저장합니다. 도중에 멈춰도 읽은 쪽은 남습니다.
- API: `POST /v1/crawls`(`url`, `max_pages`, `path_prefix`), `GET /v1/crawls/{id}`로 진행 확인, `DELETE`로 멈추기. MCP 도구 `crawl_site`도 같습니다.
  한 쪽만 바로 올릴 때는 `POST /v1/documents/url`을 씁니다.
- 사내망·내부 주소는 읽지 않습니다. 자바스크립트로만 그리는 페이지는 글이 거의 없을 수 있고, 그때는 답에서 그렇게 알려 줍니다.

### 우리 회사 소개 문서 (회사소개 태그)

- 회사 소개 문서를 `회사소개`(또는 `company-profile`) 태그로 올려 두면, 질문에 "우리 회사", "저희", "협력", "제휴"가 있을 때 그 문서를 근거에 함께 넣습니다.
- 그래서 "https://… 를 보고 우리 회사에 도움될 협력 제안을 고민해 보자"처럼 상대 사이트와 우리 회사를 함께 놓고 제안할 수 있습니다.
- 회사 소개에는 하는 일, 강점, 주요 고객, 사업 방식, 협력할 때 줄 수 있는 것을 적으면 좋습니다.

### 7. 코드 저장소 지식

- `repo-sync`로 git 저장소의 문서, 코드 지도(모듈·파일·클래스·함수·HTTP 엔드포인트), 최근 변경 이력을 올리면
  "그 API는 어디 있어?", "최근에 무엇이 바뀌었어?"에 답합니다.
- 코드 지도는 영어 식별자로 되어 있으니, 질문에 함수·경로 이름(예: `/v1/board`, `GoalManager`)을 넣으면 더 잘 찾습니다.

## MCP 연결

MCP(Model Context Protocol)는 AI가 외부 도구를 쓰는 표준입니다. Baryon AX는 두 방향으로 MCP를 씁니다.

### Baryon AX가 제공하는 MCP 도구 (다른 AI 도구에서 사용)

주소는 `POST /mcp`이고, 호출한 사람의 권한으로 동작합니다(문서 권한·감사·지식 공백이 웹과 같음).

| 도구 | 하는 일 |
| --- | --- |
| `search_documents` | 열람 가능한 문서에서 관련 부분 찾기 (문서 제목·청크와 함께) |
| `ask` | 근거와 출처가 붙은 답. 답하지 못한 질문은 지식 공백으로 기록 |
| `list_knowledge_gaps` | 답하지 못한 질문 목록 (관리자) |
| `suggest_questions` | 동료에게 물어볼 만한 질문 (공백 우선, 그다음 암묵지 질문 틀) |
| `record_answer` | 사람이 준 답을 초안으로 저장 |
| `publish_answer` | 초안을 게시해 검색에 넣고 공백을 닫음 (작성자나 관리자) |
| `crawl_site` | 웹사이트를 백그라운드로 크롤링해 문서로 저장, `crawl_id`로 진행 확인 |

### 음성 비서가 쓰는 MCP 연결 (비서가 일을 하는 도구)

| 연결 | 하는 일 |
| --- | --- |
| baryon-ax | 회사 규정·업무 절차·사내 지식 질문에 근거를 찾아 답 |
| 목표 에이전트 (goals) | 코딩·조사를 백그라운드 에이전트에 맡기고 번호로 관리 |
| 메모리 (memory) | 비서가 주인에 대해 기억하는 것 |
| 폰 알림 (phone) | 알림·알람 예약, 목록, 취소 |
| 화면 카드 (screen) | 목록·표·막대/선 차트·숫자 카드를 앱에 표시 |
| 슬랙 (slack) | 메시지 검색, 채널 읽기, 확인 후 답장 |
| DureClaw 플릿 | 다른 머신에 일 보내기(윈도우 빌드, 브라우저 조작, 카카오톡 읽기·보내기) |
| 사내 할 일 관리 | 할 일 조회·생성 |
| 메일·일정 (gog) | Gmail 검색·읽기·보내기, Google 캘린더 조회·빈 시간·일정 등록 |

- 어떤 MCP를 켤지는 앱 설정의 '비서에게 알려 주기 > 연결(MCP)'에서 고릅니다. 실제로 연결된 목록은 설치마다 다릅니다.
- 읽기만 하는 도구는 바로 쓰고, 무언가를 바꾸거나 보내는 도구는 확인을 받습니다.

## 이렇게 물어보세요

- "법인카드 해외 결제 한도는 얼마야?" → 규정 문서에서 근거와 함께 답
- "출장비 정산은 어느 시스템에 올려?" → 문서에 없으면 지식 공백으로 남고 전문가에게 질문이 갑니다
- "아직 답이 없는 질문 보여 줘" (관리자) → 지식 공백 목록
- "최근에 무엇이 바뀌었어?" → 코드 저장소 변경 이력에서 요약
- "`/v1/board`는 어디에 구현돼 있어?" → 코드 지도에서 파일 위치

## 자주 묻는 것

- **답이 틀렸어요.** 답 아래 출처 문서를 확인하고, 문서가 오래됐으면 새 문서를 올리거나 관리자에게 알려 주세요.
  웹에서는 답변 피드백을 남길 수 있습니다.
- **"찾지 못했다"고만 해요.** 문서에 없는 내용입니다. 그 질문은 지식 공백으로 기록되어 전문가에게 갑니다.
- **다른 팀 문서가 안 보여요.** 문서마다 열람 역할이 정해져 있습니다. 권한은 관리자에게 요청하세요.
- **슬랙에서 파일을 올렸는데 못 읽어요.** 봇에 `files:read` 권한이 필요합니다. 위 "슬랙 봇 권한과 문제 해결"을 보세요.
- **데이터는 어디로 가나요?** 문서, 질문, 음성은 회사 서버 안에서만 처리됩니다. 모델도 사내 서버에서 고를 수 있습니다.
